## 사용자 피드백 반영

- 사용자 재피드백에 따라 네 개의 독립된 장면으로 나눴던 변경을 철회했다. 첫 레퍼런스의 **한 화면 고정 / 왼쪽 큰 제목과 기능 목록 / 오른쪽 기울어진 폰** 형식을 복원했다.
- 전체 500svh의 네이티브 롱스크롤에서 레미 AI → 헬스장 성장 → 운동 리포트 → 운동과 전투 순서로 활성 설명과 폰 화면이 함께 바뀐다. 목록은 탭 버튼이 아니라 읽기 전용 제목이다. 휠 잠금/스크롤 스냅은 없다.
- 폰 프레임은 고정하고 안쪽 실제 앱 기반 화면을 세로로 이동한다. 비활성 화면에는 inert/aria-hidden을 적용해 숨은 버튼이 포커스를 받지 않는다. 상세 화면 구성은 유지하되 원본 토스 카드 그래픽의 픽셀 복제라고 주장하지 않는다.
- `레미와 운동해 보기` 등 항목별 CTA 링크를 전부 제거했다. 실제 데모 조작 버튼은 유지했다.
- 기존 개선 스킬의 범위 제한에 따라 Next/React/Motion을 유지하고 첫 소개 구간만 교체했다. 아래 MY GYM·티어·리포트 카드 및 레미 9단계 시퀀스는 유지한다.

`운동결과1B`의 날짜·탭·총 볼륨 그래프·누적 중량·운동 횟수·최다 운동·최다 부위·하단 버튼을 HTML/SVG로 구성했다. 캡처를 이미지로 띄우지 않는다.

- 처음 45%에 그래프가 그려지고 볼륨은 0 → 686kg으로 증가한다.
- 이후 누적 중량 패널과 운동 횟수 셀이 차례로 나타나며 마지막에 최다 운동/부위가 채워진다.

## 레미 AI 모션

### 실제 응답 규칙을 반영한 결과형 데모 (최신)

앱의 `frontend/src/screens/RemiScreens.tsx`는 서버 reply를 문단 컴포넌트로 표시하며, 현재 응답 전체를 받은 뒤 렌더링한다. `backend/supabase/functions/ai-partner-turn/persona.ts`의 규칙은 해요체 직접 답변, 루틴의 세트·반복·휴식, 참고용 제안 표시, 사용자명 호칭이다. 기록 피드백은 구체적인 기록 요약과 해석 범위를 요구한다.

- 이 규칙을 참고해 고정 데모를 재작성했다. 실제 API를 호출하거나 실응답을 캡처한 것은 아니다. 앱 소스는 읽기만 했다.
- 루틴은 세 종목 각각 세트·반복·휴식과 짧은 조절 안내, 추천은 세 부위의 종목 및 동작 설명, 식단은 하루 메뉴와 짧은 조절 설명으로 구성했다.
- 기록 피드백은 리포트의 27회 전체를 실제로 조회한 것처럼 말하지 않는다. 예시 질문에 벤치 프레스 20kg×12회×3세트를 명시하고, 답변은 해당 기록과 총 36회만 해석한다. 제공되지 않은 지난달 추세/체력 향상 주장은 제거했다.
- 추가 질문·대기 단계·가짜 토큰 스트리밍 없이 결과 문단을 짧게 페이드한다. 실제 앱의 민트색 문단과 사용자 말풍선 형식을 유지하며 새로운 결과 카드나 표는 만들지 않았다.
- 답변 쪽 캐릭터를 축소해 본문 공간을 확보했다. 원본 393×852 좌표에서 네 답변 하단은 562~614px로 입력창 689px 이전에 끝난다. 사용자 말풍선과 답변도 겹치지 않는다. 추가 내부 스크롤 없음.
- 브라우저에서 네 버튼과 뒤로 복귀, 각 결과 및 경계를 확인했다. 증빙은 `reports/experience/remi-realistic-results.png`. 아래의 이전 응답 설명은 이 변경으로 대체한다. 배포 없음.

최신 수정: 네 기능 모두 정보 수집 질문/준비 타이머 없이 결과를 바로 보여준다. 루틴 생성은 워밍업·푸쉬업·체스트 프레스 구성, 운동 추천은 상체 세 종목, 기록 피드백은 27회·686kg 및 최다 운동/부위 요약, 식단 추천은 아침·점심·저녁 예시 메뉴다. 기존 응답 화면 배치와 짧은 페이드만 유지한다. 모두 고정된 데모 결과이며 사용자 신체 정보를 실제로 분석한 결과는 아니다. 아래 650ms 준비 표시 설명은 이전 이력이다.

원본 네 버튼 `루틴 생성 / 운동 추천 / 기록 피드백 / 식단 추천`을 동일한 2×2 위치로 구성했다. 클릭하면 검은 사용자 말풍선 → 650ms 준비 표시 → 민트색 답변이 나타난다. 뒤로 버튼으로 네 질문에 돌아간다.

네 가지 응답은 서로 다른 **고정 데모 문구**다. 루틴 생성은 QA 문구의 조건 확인 방식을 요약했고, 나머지는 해당 기능을 설명하는 예시로 작성했다. 실제 AI 요청, 녹음, 네트워크 전송, 저장은 없다. 응답 화면 전체를 실제 앱과 픽셀 단위로 복제했다고 주장하지 않는다.

화면 이탈/다른 기능 전환/언마운트 시 준비 타이머를 해제한다. 모션 감소에서는 응답을 즉시 표시하고 폰 기울기·세로 전환 이동을 제거한다. 기능 선택은 여전히 네이티브 스크롤을 따른다.

## 형식 복원 후 확인

세트 수 의미 정정: 앱의 숫자는 남은 세트/전체 세트다. 마지막 세트 시퀀스(5–7단계)에서는 현재 종목 외 세 종목을 완료 체크로 유지하고, 현재 체스트 프레스만 `1/4 → 0/4 → ✓`로 진행한다. 완료된 다른 종목은 재수행 클릭을 막았다. 운동 목록·배치·중량 조정값은 유지한다. 앞선 4/4 유지 설명은 이 변경으로 대체한다.

전투 목록 후속 수정: 공격/완료 단계에서 `exercises.slice(4,5)`로 종목을 마지막 하나로 교체하고 빈 카드 3개를 넣던 분기를 제거했다. 공유 Battle 컴포넌트는 항상 기존 네 종목(푸쉬업·체스트 프레스·바벨 로우·래터럴 레이즈)을 같은 순서로 유지한다. 공격은 현재 종목 상태만 바꾸고 완료는 네 카드 모두 체크를 표시한다. 브라우저에서 단계 5/6/7의 동일 종목 ID 및 완료 체크 4개, 빈 카드 0개를 확인했다. 빌드 및 기존 검사 통과. 로컬만 반영했다.

후속 변경: 드래그 UI 제거 후 브라우저에서 휠 스크롤만으로 40kg 중간 상태 → 686kg·운동 1회 상태가 표시되는 것을 확인했다. 소개 구간의 input은 0개다. 슬라이더 없는 결과 캡처는 `reports/experience/overview-report-scroll.png`에 저장했다. 아래 range 검증은 제거 전 이력이다.

- 고정 stage가 하나이고, 네 기능 제목은 링크나 탭이 아닌 읽기 전용 목록임을 확인했다. 아래 성장 카드/레미 여정 코드는 변경하지 않았다.
- 실제 브라우저에서 휠 스크롤로 레미 AI → 리포트 전환, 네 질문 중 루틴 생성 응답/뒤로 복귀, 리포트 range End 키로 100%·686kg·1회 완성을 확인했다.
- 키보드 포커스로 overflow:hidden 내부가 자동 스크롤되던 정렬 오차를 overflow:clip으로 수정했다. 정착 후 폰 안쪽의 다음 화면이 비치지 않음을 확인했다.
- 1154×956 및 390×844에서 가로 오버플로 없음과 리사이즈 후 폰 화면 정렬을 확인했다. 임시 뷰포트는 복원했다.
- 빌드 18페이지 생성, 기존 7경로 및 에셋 51개 검사 통과. 포인터 드래그/실제 터치/OS 모션 감소 실기 테스트는 미실시이며, 픽셀 일치 검증은 아니다.
