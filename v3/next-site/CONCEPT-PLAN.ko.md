# SPOT ME 소개 페이지 재설계 · 2026-09-28

## 범위와 방향

사용자 승인: 기존 Figma 배치를 벗어나 전달 에셋, 이미지 생성, 토스 레퍼런스를 적극적으로 활용한다. 새 로컬 경로 `/concept/`, 검토 경로 `/concept/review/`. 기존 홈·5개 메뉴 경로·배포 설정은 유지한다. 배포 및 Git push는 하지 않는다.

Design Read: 운동을 시작하거나 꾸준히 이어가고 싶은 방문자에게, 기능 → 동기 → 시작 과정을 명확하게 설명하는 스포츠 제품 소개로 전면 재구성한다.

설계 다이얼: DESIGN_VARIANCE 6 / MOTION_INTENSITY 5 / VISUAL_DENSITY 3. 큰 한국어 타이포그래피, 단정한 선택 반응, 실제 화면 중심. 강제 스크롤 전환·반복 흔들림·무의미한 패럴랙스는 사용하지 않는다.

## 레퍼런스 인덱스 변경

| 새 번호 | 종전 번호 | 토스 레퍼런스 | SPOT ME 적용 |
| --- | --- | --- | --- |
| 01 | 03 | 자산을 관리하는 일은 한껏 단순하게 | 루틴·레미 대화·리포트의 동등한 기능 선택, 선택에 맞춘 실제 화면 |
| 02 | 01 | 대출·카드·보험 그래픽 카드 | 퀘스트·랭킹·헬스장이라는 운동 지속 동기를 시각적으로 요약 |
| 03 | 02 | 최저가는 알아서 찾아주고 | 운동 수준 설정 → 루틴 준비 → 운동 시작. 폰과 체크포인트 동기화 |

참고: https://toss.im/ 의 앞선 브라우저 관찰. 외부 서비스의 사유 에셋/로고/카피는 복사하지 않는다.

## 콘텐츠 적절성 판단

1. 기능 목록은 독립 기능을 비교하는 데 적합하다. 루틴·대화·리포트를 순서대로 해야 하는 단계처럼 표현하지 않는다.
2. 그래픽 카드는 퀘스트/보상/성장이라는 개념 이해에 적합하다. 생성된 헬스장 일러스트를 실제 앱 UI라고 소개하지 않고 클릭하면 전달된 원본 화면이 열린다.
3. 사용 과정은 인과관계가 있는 한 흐름에만 적용한다. 운동 수준 설정의 중급 선택과 루틴 준비의 중급 표시는 일치한다. 중간 단계가 생략됐으며 동일 계정의 녹화는 아니다.
4. 운동진행3-4B(중량 변경 제안)와 3-4C(다른 운동법 질문 답변)는 같은 작업의 전후 화면으로 묶지 않는다.
5. 추천 품질·자동 기록 정확성·대화 응답·서버 저장·출시 여부는 디자인 에셋으로 입증할 수 없으므로 미검증으로 남긴다.

## 문구와 화면 매핑

정확한 현재 문구·근거 노드·주의사항은 `src/concept/content.js`에서 한 번만 정의하고 소개 화면과 검토 화면이 공유한다.

- 기능: `1_운동_AI추천운동`, `1_운동 - 운동진행3-4B`, `3_리포트2`. 초기 후보였던 레미AI_03은 독립 상담 화면이므로, '운동 중' 설명에 더 맞는 중량 수정 제안 원본으로 교체했다.
- 가치: `1_운동_퀘스트_주간퀘스트_조건달성`, `4_랭킹_이번달`, `1_운동_헬스장키우기`
- 과정: `운동수준2C`, `운동루틴준비2`, `1_운동_c_01`
- 브랜드: 전달 로고 B, 홈 레미 A_01. 수정 없이 사용.
- 헤드라인은 새 편집 문구다. 효과 보장이나 수치 주장은 하지 않는다.
- 원본 경로 및 SHA-256은 `public/concept/assets/manifest.json`에 저장한다.

## 이미지 생성

내장 이미지 생성으로 가로 섹션 시안 3장과 기능 카드용 설명 일러스트 1장을 생성했다. `public/concept/generated/`에 보관. 프롬프트는 `concept-image-prompts.json`.

- 01: 왼쪽 기능 목록, 오른쪽 실제 앱 강조
- 02: 퀘스트·랭킹·헬스장을 설명하는 세 그래픽 카드
- 03: 폰 왼쪽, 체크포인트 오른쪽
- 별도 설명 그림: 덤벨과 치즈 / 단상 / 미니어처 헬스장

생성 시안의 변형된 로고, 임의로 재생성된 앱 UI와 텍스트는 구현 자산으로 사용하지 않았다. 원본 화면과 실제 HTML 문구로 대체한다. 생성 이미지는 디자인 참고이며 픽셀 일치 검증 대상이 아니다.

## 구현

- Next.js 기존 프로젝트 안에 독립 경로 추가. 기존 페이지 대체 없음.
- 첫 기능 선택: 버튼/방향키/Home/End. 선택 시 실제 화면 크로스페이드.
- 카드: 설명 일러스트 → 버튼 → 원본 화면 dialog. Escape/닫기 지원.
- 과정: 데스크톱 sticky 폰 + 전체 체크포인트를 유지하고 Motion 스크롤 진행률로 단계 동기화. 상태 갱신은 3개 단계 경계를 넘을 때만 발생한다. 클릭/키보드로도 단계 선택 가능. 모바일은 각 단계에 원본 이미지를 함께 보여준다.
- 기존 전 페이지 이미지 사전 로딩과 페이지 전환은 concept 경로에서 제외해 불필요한 데이터 로딩/민트 깜빡임을 방지한다.
- reduced-motion에서 화면 페이드·등장 이동·호버 이동 제거. 사용자의 스크롤은 가로채지 않는다. 색상 모드에 맞춰 명도 조정.
- JS가 없어도 핵심 문장과 첫 화면, 모바일 단계 이미지를 읽을 수 있다. 상호작용은 JS 필요.

## 다음 승인 사항

- 세 메시지 묶음이 실제 출시 기능과 일치하는지 제품 담당 확인.
- 연속 시퀀스를 실제 실행 화면으로 교체하려면 동일 계정/동일 루틴의 캡처 필요.
- 현재는 소개 방향을 비교하는 로컬 초안이다. 전체 상세 페이지 리디자인 및 배포는 별도 단계.

## 검증 기록

- 최종 `npm run build` 성공(경고 없음). 빌드된 로컬 서버 `http://127.0.0.1:4193/concept/`, 검토표 `/concept/review/`. 개발 서버 4189도 유지.
- `node scripts/check-concept.mjs`: 통과. 원본/서비스 복사본 11개 해시, 문구 근거 9건, 생성 이미지 4개, 섹션 순서, 서버 렌더링, 새 2개·기존 5개 경로 200.
- 데스크톱 1440×1000: 방향키·End로 기능 선택, 팝업 Enter 열기/Escape 닫기, 체크포인트 선택 및 실제 스크롤에 따른 화면 동기화 확인.
- 모바일 390×844: 페이지 가로 넘침 없음, 5개 메뉴 모두 줄바꿈으로 노출, 선택 기능 작동, 3개 과정의 화면 각각 표시.
- 태블릿 768×1024: 가로 넘침 없음, 2열 유지.
- 브라우저 콘솔 오류 없음(확인 시점).
- reduced-motion 분기는 코드 검토 완료. 운영체제 설정을 바꾼 실기 검증은 미실시.
- 브라우저 현재 다크 환경으로 확인. 밝은 테마 및 실물 모바일, Lighthouse 성능 점수는 추가 검증 필요.
- 앱 실행/서버 연동 검증은 수행하지 않았다. 디자인 증거와 제품 기능 검증을 혼동하지 않는다.

## 2026-09-29: SPOT ME 인터랙티브 시안으로 발전

추가 논의를 반영해 `/concept/`의 진입 컴포넌트를 새 시안으로 교체했다. 이전 `Concept.jsx`와 관련 에셋은 삭제하지 않았고, 원본 비교 경로 `/concept/reference/`도 유지했다.

순서는 기능 개요, 헬스장·티어·리포트 가치 카드, 레미 AI 사용 시퀀스다. 게임 전투는 개요에서 짧게만 소개한다. 사용자가 허용한 앱 저장소의 에셋·컴포넌트·디자인 캡처를 읽고, 실제 그림과 HTML/SVG로 조작 가능한 샘플을 구성했다. 앱 저장소를 수정하지 않았다.

헬스장 전후 비교 슬라이더, 티어 배지 전환, 월별 리포트, 시간 선택, 중량 수정, 다음 세트 준비 드래그/탭 대안을 구현했다. 리포트 계산은 실제 앱의 게스트 예시 데이터 식과 일치한다. 사이트가 실제 AI에 질의하거나 기록·보상을 저장하지는 않는다.

상세 근거, 구현 범위와 검증은 `EXPERIENCE-IMPLEMENTATION.ko.md`, 에셋 경로와 해시는 `public/concept/experience/manifest.json`에 기록했다. 로컬 전용이며 배포·푸시는 하지 않았다.

### MY GYM 후속 피드백 반영

사용자가 지정한 토스 폰 프레임에 SPOT ME 헬스장 원본을 배치했다. 전후 드래그 비교를 호버 전환으로 교체하고, 성장 화면 전환 시 한 번만 지나가는 광택을 추가했다. 탭/Enter 대안과 Escape 초기화를 지원한다. TIER·REPORT는 유지하며 현재 수정은 로컬 비교용이다.
